# 情侣日记云开发配置

## 1. 启用云开发

在微信开发者工具中打开项目，进入“云开发”，为当前体验版小程序创建默认云环境。代码使用 `wx.cloud.init({ traceUser: true })` 初始化默认环境。

## 2. 创建集合

创建三个数据库集合：

- `diaries`
- `custom_options`
- `locked_plans`

## 3. 集合权限

体验版首版只给两位体验成员使用，推荐这样配置：

- `custom_options`：所有用户可读，仅创建者可读写。小程序前端只直接读取这个集合；新增、编辑、删除、排序统一通过 `manageOptions` 云函数写入，避免被“仅创建者可写”卡住。
- `diaries`：所有用户可读，仅创建者可读写，或按实际体验版需要放宽到两位体验成员都可读写。如果希望两个人互相编辑同一天日记，后续也应改为云函数写入。
- `locked_plans`：所有用户可读，仅创建者可读写，或按实际体验版需要放宽到两位体验成员都可读写。如果希望两个人都能重置/锁定同一天结果，后续也应改为云函数写入。

未来如果小程序发布给更多人使用，必须改成云函数写入，并基于 OpenID 或情侣空间 ID 做访问控制。

## 4. 管理选项云函数

创建并上传云函数：

- 函数名：`manageOptions`
- 本地目录：`cloudfunctions/manageOptions`
- 作用：写入 `custom_options` 集合，处理今天干什么选项的新增、编辑、删除、排序。

上传方式：

1. 在微信开发者工具左侧找到 `cloudfunctions/manageOptions`。
2. 右键该目录。
3. 选择“上传并部署：云端安装依赖”。
4. 部署完成后，重新编译小程序。

默认体验版没有配置 OpenID 白名单时，云函数允许当前小程序用户调用。若以后不只两位体验成员使用，请在云函数环境变量中设置：

`OPTION_ADMIN_OPENIDS=openid1,openid2`

设置后，只有这两个 OpenID 可以增删改排选项。

## 5. 基础同步

“今天干什么”页面会在这些时机同步 `custom_options`：

- 页面首次进入时同步一次。
- 从后台回到前台时同步一次。
- 停留在页面期间每 15 秒自动刷新一次。
- 自己新增、编辑、删除、排序成功后会立即更新本地显示。

这不是毫秒级实时监听；另一台设备修改后，本机最多等十几秒看到变化。

## 6. 索引

`diaries` 集合不需要手动创建唯一索引。

当前代码会把日记写入确定性文档 ID：`diary_YYYY_MM_DD`，这已经能保证“一天一篇”。如果额外创建 `date` 唯一索引，配置稍有错误就可能导致只能保存一条日记，并报 `dup key: { : null }`。

如果已经创建过 `date` 唯一索引，建议删除这个索引后再测试保存多天日记。

## 7. 云存储

日记照片上传到路径：

`diaries/<YYYY-MM-DD>/<timestamp>-<index>.<ext>`

不要手动清理这些文件，因为首版不提供日记删除功能。

## 8. 验收清单

- 两台设备都能打开“我们的日记”。
- A 设备保存 `2026-06-04` 日记后，B 设备刷新能看到同一篇。
- B 设备编辑同一天并保存后，A 设备刷新看到 B 的版本。
- 未保存退出后再次进入同一天，能恢复本地草稿。
- 保存失败时草稿不丢失。
- 新标签确认后，重新进入“今天干什么”能在对应大分类的“其他”分组看到它。
- A 设备新增、编辑、删除、排序“今天干什么”选项后，B 设备重新进入页面或等待 15 秒左右能看到变化。
- 打开月历后，过去日期可以补写，未来日期会提示不能写。
- 任一设备点击 `Perfect` 后，另一台设备普通打开小程序也会进入“今日已定”页面。

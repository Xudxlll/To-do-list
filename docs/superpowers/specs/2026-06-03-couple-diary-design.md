# 情侣日记功能设计

## 1. 背景与目标

当前小程序用于情侣共同决定“今天怎么过”，已有欢迎页、随性记录页、分类选择页和结果页。新增“情侣日记”功能，用于长期记录两个人每天一起做了什么。

情侣日记是一个独立功能空间，不与“今天干什么”的当天选择流程联动。它们只共享同一套可复用的活动标签选项库。

首版目标：

- 两位体验成员可以查看和编辑同一份共同日记。
- 每个自然日最多只有一篇日记。
- 支持补写任意过去日期，禁止创建未来日期日记。
- 记录过程轻量，正文是一段自由文本，不要求填写标题。
- 日记内容可识别为“今天干什么”中的活动标签，并允许将新标签沉淀到共享选项库。

## 2. 已确认的产品规则

### 2.1 使用范围与权限

- 小程序当前为体验版，只有用户和女朋友可以使用。
- 首版不新增情侣邀请、账号绑定、OpenID 白名单或额外身份校验。
- 任何能够进入该体验版小程序的成员都可以查看和编辑全部日记。

这依赖体验版成员范围，不构成日记数据本身的权限保护。若未来发布范围扩大，必须重新设计访问控制。

### 2.2 日记规则

- 同一天只有一篇共同日记。
- 两个人编辑的是同一份内容，不拆分为“我写的”和“女朋友写的”。
- 日记创建后不允许删除，只能继续编辑。
- 两个人同时编辑时，后保存的版本直接覆盖先保存的版本。
- 编辑内容在本地自动暂存，只有点击保存后才同步到共同日记。
- 同一天重复尝试新建时，直接打开已有日记编辑页。

### 2.3 日记字段

每篇日记包含：

- 日期，必填，格式为 `YYYY-MM-DD`
- 正文，必填，一段自由文本
- 心情，必填，选择一个心情表情
- 地点，选填，手动输入地点名称
- 照片，选填，最多 3 张
- 标签，由正文自动识别并在保存前确认
- 创建时间与更新时间，由系统维护

日记不包含标题。首页卡片使用正文摘要代替标题。

## 3. 页面结构与交互

### 3.1 欢迎页入口

在现有欢迎页右上角增加“📖 我们的日记”独立卡片。

- 保留当前底部“今天不安排，随性过”和“来看看今天干啥”两个主操作。
- 日记入口视觉上是长期存在的回忆空间，不作为第三个底部按钮。

### 3.2 日记首页

日记首页采用“时间线 + 月历入口”的混合结构。

顶部展示当月概览和进入完整月历的入口，主体按日期从新到旧展示日记卡片。卡片显示：

- 日期
- 心情表情
- 正文摘要
- 地点，存在时显示
- 已确认标签
- 第一张照片作为封面，存在时显示

首页提供新建今日日记的入口。如果今天已经有日记，入口改为编辑今日日记。

### 3.3 月历页

月历页用于查找和补写日记。

- 有日记的日期显示已记录状态。
- 点击已有日期打开该日记编辑页。
- 点击过去的空白日期新建该日日记。
- 点击未来日期不执行创建，并保持不可用视觉状态。

### 3.4 日记编辑页

编辑页支持创建和编辑同一套字段：

- 日期
- 单选心情表情
- 自由正文
- 手动输入地点
- 最多 3 张照片
- 自动识别后的标签确认

输入正文、地点、心情或选择照片后，本地草稿自动更新。点击保存时才上传照片、确认标签并写入云端共同日记。

## 4. 技术方案

### 4.1 总体方案

采用“云端日记 + 静态预设分类 + 云端新增标签”的方案。

- 保留 `miniprogram/data/categories.ts` 作为现有预设分类和预设选项来源。
- 使用微信云开发数据库保存共同日记和后来确认的新标签。
- 使用微信云存储保存日记照片。
- “今天干什么”页面加载时，将云端新增标签合并到对应大分类的“其他”分组。
- 在小程序启动时初始化指定的微信云开发环境。
- 将 `diaries` 和 `custom_options` 集合配置为体验成员可读写，确保两个人编辑的是同一份数据。

不把全部预设分类迁移到云数据库，避免重构现有选择页和增加首屏加载风险。

体验成员可读写是一项部署配置，不是严格的数据隔离方案。未来扩大使用范围前，必须改为基于身份的云函数写入和访问控制。

### 4.2 云端数据模型

#### `diaries` 集合

```ts
interface DiaryRecord {
  _id: string;
  date: string;
  content: string;
  mood: string;
  location: string;
  photoFileIds: string[];
  tags: DiaryTag[];
  createdAt: number;
  updatedAt: number;
}

interface DiaryTag {
  categoryId: string;
  optionId: string;
  name: string;
  isCustom: boolean;
}
```

`date` 必须在集合中保持唯一。保存时按日期查询并执行新增或更新，从产品层保证每天只有一篇。

为 `date` 配置唯一索引，避免两台设备同时首次保存同一天日记时产生两条记录。

#### `custom_options` 集合

```ts
interface CustomOptionRecord {
  _id: string;
  categoryId: string;
  name: string;
  normalizedName: string;
  createdAt: number;
}
```

- 每条记录属于一个现有大分类。
- `normalizedName` 用于避免同一大分类下创建重复的新标签。
- 这些记录在“今天干什么”中显示在该大分类的“其他”分组。

### 4.3 本地草稿

本地草稿使用微信存储保存，按日期区分：

```ts
interface DiaryDraft {
  date: string;
  content: string;
  mood: string;
  location: string;
  localPhotoPaths: string[];
  updatedAt: number;
}
```

- 草稿键名按日期生成，例如 `diaryDraft:2026-06-03`。
- 进入编辑页时，如果本地草稿比云端记录更新，则提示继续编辑草稿。
- 云端保存成功后清除对应日期的本地草稿。
- 保存失败、照片上传失败或退出编辑页时保留草稿。

## 5. 自动标签设计

### 5.1 边界

日记和“今天干什么”不共享当天选择状态，只共享标签选项库：

- 日记不会读取当天已选择的活动。
- 日记标签不会自动勾选“今天干什么”的选项。
- 点击 `Perfect!` 不会生成日记。
- 今日计划不会自动成为日记内容。

### 5.2 识别来源

首版不使用 AI 或第三方内容分析服务。自动标签完全在本地完成，输入来源为日记正文。

识别顺序：

1. 将正文与现有预设选项名称进行匹配。
2. 将正文与云端新增标签名称进行匹配。
3. 使用维护在本地配置中的“大分类关键词 + 活动动词”规则，判断仍未覆盖的句子属于哪个现有大分类。
4. 从命中规则的短句中提取活动动词后的短语，生成候选新标签。例如“去看了油画展”命中“看”类规则，并提出“油画展”候选标签。

本地规则只对命中配置规则的内容提出新标签，不承诺理解任意自然语言。未命中规则的内容不会自动创建标签。所有新标签都必须在保存前由用户确认和修正。

### 5.3 标签确认层

点击保存后，先展示标签确认层：

- 展示已匹配的现有标签及所属大分类。
- 展示准备新建的标签及推断的大分类。
- 允许修改新标签名称。
- 允许切换新标签所属大分类。
- 允许删除不准确的标签。

确认后：

- 标签写入当前日记。
- 新标签写入 `custom_options` 集合。
- 新标签以后显示在“今天干什么”对应大分类的“其他”分组。

## 6. 数据流

### 6.1 加载日记首页

1. 从云数据库读取最近日记，按日期倒序排序。
2. 从云数据库读取本月有日记的日期，用于月度概览。
3. 加载成功后渲染时间线。
4. 加载失败时显示明确的失败状态和重试按钮，不显示为“还没有日记”。

### 6.2 创建或编辑日记

1. 根据日期查询云端是否已有日记。
2. 同时读取该日期的本地草稿。
3. 如果草稿更新时间晚于云端更新时间，提示继续编辑草稿。
4. 用户修改内容时持续更新本地草稿。
5. 用户点击保存后，执行本地标签识别并打开标签确认层。
6. 用户确认标签后上传新增照片。
7. 照片全部上传成功后，按日期新增或更新云端日记。
8. 保存成功后清除本地草稿并返回日记首页。

### 6.3 加载“今天干什么”选项

1. 先使用 `categories.ts` 中的预设分类和选项构建页面数据。
2. 从云数据库读取 `custom_options`。
3. 将新增标签按 `categoryId` 合并到对应大分类的“其他”分组。
4. 云端新增标签加载失败时，仍显示本地预设选项，并提示新增标签暂未加载。

## 7. 异常处理

- 云端日记加载失败：显示重试按钮，不显示空状态。
- 本地草稿存在：提示用户继续编辑草稿。
- 照片上传失败：不保存日记，保留草稿，并提示重新上传。
- 云端保存失败：不清空草稿，允许再次保存。
- 同日重复创建：打开已有日记编辑页。
- 未来日期：不可创建。
- 新标签重复：按大分类和规范化名称复用已有标签。
- 云端新增标签加载失败：“今天干什么”仍可使用预设选项。
- 唯一索引冲突：重新读取该日期已有日记，再按后保存覆盖规则执行更新。
- 两人同时编辑：后保存的内容覆盖先保存的内容，不做冲突提示。

## 8. 首版不包含

- 情侣邀请、账号绑定、OpenID 白名单和额外权限控制
- 日记删除、回收站和版本历史
- AI 标签分析和第三方内容上传
- 富文本、评论、点赞和日记分享
- 自动读取今日选择或从今日计划生成日记
- 多设备编辑锁和保存冲突提示
- 地图地点选择和位置权限

## 9. 验收标准

- 欢迎页右上角可以进入“我们的日记”，现有两个主操作不受影响。
- 两位体验成员可以看到同一份云端日记列表和日记内容。
- 云开发环境、集合权限和 `diaries.date` 唯一索引已正确配置。
- 每个日期最多只有一篇日记，重复新建会进入编辑。
- 可以创建今天或任意过去日期的日记，不能创建未来日期日记。
- 每篇日记可以保存一段正文、一个心情、选填地点和最多 3 张照片。
- 日记创建后没有删除入口，只能编辑。
- 编辑退出后草稿仍在，保存成功后草稿被清除。
- 云端或照片保存失败时草稿不会丢失。
- 保存前可以确认、修改或删除自动识别标签。
- 经确认的新标签会出现在“今天干什么”对应大分类的“其他”分组。
- 日记不会自动读取、修改或生成“今天干什么”的当天选择。
